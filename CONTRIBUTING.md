# Contributing

Thank you for your interest in improving the HiTechCloud CRM SDK.

## Repository layout

```
sdk/nodejs    TypeScript SDK  (@hitechcloud-vietnam/crm-sdk)
sdk/python    Python SDK      (hitechcloud-crm)
sdk/php       PHP SDK         (hitechcloud-vietnam/crm-sdk)
sdk/go        Go SDK          (github.com/hitechcloud-vietnam/hitechcloud-crm-sdk/go)
sdk/java      Java SDK        (vn.hitechcloud:crm-sdk)
mcp           Node.js MCP server
docs          Vietnamese documentation
examples      Runnable examples per language
openapi.json  OpenAPI 3.0.3 specification (generated by scripts/gen_openapi.py)
```

## Source of truth

All endpoints are derived from the public CRM API reference
(`https://developers.hitechcloud.vn`). When the API changes, update
`scripts/gen_openapi.py`, regenerate `openapi.json`, then mirror the change in
each language SDK.

```bash
python3 scripts/gen_openapi.py
```

## Development workflow

1. Fork the repository and create a feature branch.
2. Make your change in **every** language SDK so they stay in sync.
3. Keep public method names and resource accessors identical across languages
   where the language's conventions allow.
4. Add or update tests and examples.
5. Run the per-language checks below.
6. Open a pull request describing the change.

## Local checks

```bash
# Python
cd sdk/python && python -m py_compile hitechcloud_crm/*.py && pytest

# Node.js / TypeScript
cd sdk/nodejs && npm install && npm run build && npm test

# PHP
cd sdk/php && php -l src/Client.php && composer test

# Go
cd sdk/go && gofmt -l . && go vet ./... && go test ./...

# Java
cd sdk/java && mvn -q test
```

## Coding guidelines

- No external dependencies beyond the documented HTTP client per language.
- Never log access tokens, client secrets or webhook secrets.
- Preserve the stable `status` / `data` / `meta` response envelope semantics.
- Use `code` (not `message`) for programmatic error handling.
